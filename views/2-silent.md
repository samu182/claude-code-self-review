# 視点2 — 無音（壊れたことが誰にも分からない形で壊れる）

- **戻り値を捨てていないか。** `save()` / `update()` が「書けなかった」を返す設計なら、呼び出し元は必ずそれを使う
  （実例: 保護のための条件で `save()` が黙って何もしなくなり、呼び出し元は成功前提で画面に「保存しました」と出していた。**DB には何も残らず、ログも無い**）
- **全列上書きしていないか。** `upsert` / `.update(row)` に状態の条件と列の絞り込みがあるか
  （実例: 夜の集計の処理が全列を書き戻し、昼に発送済みにした注文が「未発送」に巻き戻った）
- **黙って切れる上限が無いか。** 例: Supabase の既定の最大行数は1000で、`.limit(2000)` と書いても1000で切れる
- **失敗がログに残るか。** catch が握り潰していないか。`String(error)` が `[object Object]` になっていないか
- **「取得できなかった」と「0件」を区別しているか**
