# 視点4 — 二重実装・不揃い・保守性（**後回しにしても必ず台帳に残す。捨てない**）

保守性の指摘は「後回し可」だが **落とさない**。理由は、**二重実装は保守性の顔をして実害を出す**から。

- **同じことをする実装がもう1セット無いか。** これが最優先。**差分の中だけでなく、リポジトリ全体を grep する**（同じ意味の判定が `=== "a"` と `!== "b"` のように別の書き方で無いか）
  （実例: 差分内の重複は直したが、別ファイルにあった別の書き方の判定を見落とし、新しい種類の行で結果が割れた。2つの画面が同じ集計を別々に書いていて、片方ずつ直すたびにずれが戻った）
- **死んだ二重実装を新設していないか。** 部品（port / adapter）を足したのに本番の経路がそこを通っていない、という形（実例: その部品を壊してもテストは全部緑のままだった）
- **既存の資産を再実装していないか。** 日付・CSV・エラーの文字列化など、共通の部品がすでにあるもの
- **チケット外の変更が混入していないか。** 関係ない `docs/` / `scripts/` / 他人の担当範囲が 0 か
- 命名・構造・重複。**ここで挙がったものは全部、必須でなくても台帳へ**
