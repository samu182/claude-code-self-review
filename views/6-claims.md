# 視点6 — 書いたことは本当か（本文・計画・docs・コメントの主張を現物と突き合わせる）

**実測で、ほかの5視点を回すようになっても最後まで残った型。** 「確かめた」と書いたのに実際は読んだだけ、が続いていた。

- **PR 本文・計画・手順書・migration の冒頭・コード中のコメント・台帳に書いた数字と主張を、1つずつ現物で確かめる。** 数・ファイル名・環境変数名・表の名前・「〜しない」「〜だけ」の言い切り
  （実例: 本番手順書の何行かが現物と違っていた。参照している表の数を書き違えた。本文に書いた設定の名前が実在しなかった）
- **主張の強さを、確かめた強さに合わせる。** 書き分ける: **確認済み**（実行・実測した）/ **読んで確認**（コードを読んだだけ）/ **未確認**。「ロックの順で確かめた」と書くなら、実際に同時に走らせたか
  （実例: 「ロックの順で確かめた」は読んだだけで、ロックの行を消してもテストは緑だった。書籍 p534・p545 の Confirmed / Needs investigation / Not tested の書き分け）
- **出し直し・適用後に古くなる記述を直したか。** 再提出したら本文も直す。migration を当てたら冒頭の「まだ適用しない」と計画の適用表を直す
- **計画の外を触ったら本文に1行書いたか。** チーム共通の docs を触っていないか
